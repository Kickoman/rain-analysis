## Baseline Model v0.1 — простая модель предсказания дождя

**Цель:** минимально работающая модель (baseline) для future reference — проверка, что усложнения и feature engineering действительно что-то дают.

---

## Принцип работы

Модель использует текущие показания температуры и влажности, извлекая признаки за разные временные окна (1h, 3h, 6h):

- Тренды за последний час, 3 часа и 6 часов
- Пиковые значения за эти окна
- Разброс значений (range)
- Текущая влажность (абсолютное значение)

Затем накладывается взвешенная функция с фиксированными коэффициентами (версия v0.1).

### Ожидаемое качество

Нет ground truth для настоящей валидации, но на глаз:

- Модель v0.1 быстро откликается на резкий рост влажности перед дождём (humidity spike).
- Базовая оценка выглядит адекватной, но модель всё равно иногда поднимает сигнал на случайных скачках влажности.
- Очевидные направления улучшений: интеграция давления, больше экспериментов с комбинациями признаков и окон, либо ML-модель вместо эвристик.

Это отправная точка, не финальный продукт.

## Фичи

### Источники данных
- **Температура:** `sensor.datchik_klimata_temperatura` (балконный датчик Xiaomi)
- **Влажность:** `sensor.datchik_klimata_vlazhnost` (балконный датчик)
- **Давление:** `sensor.filtered_pressure` (DIY метеостанция с фильтрацией)

> **Примечание:** Baseline модель (v0.1) использует только температуру и влажность. Для моделей с интеграцией давления см. [MODELS.md](../docs/MODELS.md) — таблица с pressure-aware вариантами (`model_pressure_aware`, `model_pressure_absolute`, и др.).

### Внешние источники
- **Yandex Weather:** прогноз погоды (для сравнения)
- **Open-Meteo:** ground truth для бэктестинга (осадки)

## Порядок работы (baseline-анализ)

1. **Загрузка данных:** Home Assistant DB → pandas DataFrame с колонками `[timestamp, temperature, humidity]`
2. **Feature extraction:** функция `compute_features()` в `analysis/feature_extractor.py`
3. **Model prediction:** `model_prediction()` возвращает score для каждого timestamp
4. **Report generation:** визуализация в matplotlib + markdown summary

## Тюнинг коэффициентов (v0.1)

Коэффициенты подобраны методом "как глаз ляжет":

```python
BASELINE_WEIGHTS = {
    'humidity_trend_1h': 3.0,    # Быстрый рост влажности — сильный сигнал
    'humidity_trend_3h': 2.0,    # Плавный тренд
    'humidity_peak_6h': 0.5,     # Исторический максимум
    'current_humidity': 1.5,     # Абсолютное значение важно (95% = дождь)
    'temperature_trend_1h': -1.0, # Падение температуры часто связано с дождем
    ...
}
```

Эти значения — константы первой версии, дальнейшие улучшения:
- **Grid search** (перебор коэффициентов)
- **Gradient descent** (если есть ground truth)
- Или переход к ML-модели (Приоритет 3)

## Roadmap

### Приоритет 1: Интеграция давления

**Статус:** Экспериментальные модели с давлением реализованы в `pressure_variants.py` (см. [MODELS.md](../docs/MODELS.md)).

**Что было сделано:**
- Реализованы 5 вариантов pressure-aware моделей:
  - `model_pressure_aware`: базовая интеграция тренда давления
  - `model_pressure_absolute`: использует и тренд, и абсолютный уровень давления
  - `model_pressure_long_window`: длинные окна (6h/12h) для медленных трендов
  - `model_pressure_triple_window`: три окна (3h/6h/12h) для разных временных масштабов
  - `model_combined`: блендинг всех моделей с динамическими весами

**Что нужно далее:**
- Систематическая валидация на исторических данных
- Подбор оптимальных весов (grid search или ручной тюнинг)
- A/B тест лучшей модели vs baseline v0.1

### Приоритет 2: Ground truth validation

**Текущая проблема:** нет прямой метрики качества — только визуальная оценка.

**План:**
- Интеграция Open-Meteo API (исторические данные осадков для location)
- Метрики precision/recall по пороговым значениям score
- Confusion matrix для разных threshold (например, `[0.3, 0.5, 0.7]`)

**Статус:** Реализовано. `run_full_analysis.py` включает:
- Загрузку ground truth из Open-Meteo
- Классификацию с несколькими порогами
- Confusion matrix, F1-score, precision, recall
- Автоматическую генерацию отчёта в markdown

### Приоритет 3: ML-подход

**Идея:** перейти от ручных коэффициентов к обученной модели (Random Forest, XGBoost, etc.).

**Что для этого нужно:**
- Ground truth (см. Приоритет 2) — уже реализовано
- Фичи уже извлекаются (тренды, пики, range) — готовы к использованию
- Модуль обучения и кросс-валидация (to be implemented)
