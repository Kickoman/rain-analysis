# Глоссарий терминов и метрик

## Метрики

### Precision (точность)
Доля верно предсказанных дождей среди всех предсказаний дождя.

```
Precision = TP / (TP + FP)
```

Где:
- **TP (True Positive):** модель предсказала дождь, и он был
- **FP (False Positive):** модель предсказала дождь, но его не было

**Пример:** Если модель 10 раз сказала "будет дождь", и 7 раз оказалась права — precision = 0.7 (70%).

---

### Recall (полнота)
Доля пойманных дождей среди всех реальных дождей.

```
Recall = TP / (TP + FN)
```

Где:
- **TP (True Positive):** модель предсказала дождь, и он был
- **FN (False Negative):** модель НЕ предсказала дождь, но он был

**Пример:** Если было 10 дождей, и модель поймала 8 из них — recall = 0.8 (80%).

---

### F1-score
Гармоническое среднее между precision и recall. Баланс между точностью и полнотой.

```
F1 = 2 * (Precision * Recall) / (Precision + Recall)
```

**Интерпретация:**
- F1 = 1.0 — идеальная модель (нет ни ложных срабатываний, ни пропусков)
- F1 = 0.0 — полностью бесполезная модель
- F1 > 0.5 — модель лучше случайного угадывания (но зависит от класс-баланса)

---

### Confusion Matrix (матрица ошибок)

Таблица 2x2, показывающая все комбинации предсказаний и реальности:

```
                Predicted: Rain    Predicted: No Rain
Actual: Rain         TP                  FN
Actual: No Rain      FP                  TN
```

Где:
- **TP (True Positive):** правильно предсказан дождь
- **TN (True Negative):** правильно предсказано отсутствие дождя
- **FP (False Positive):** ложная тревога (дождя не было)
- **FN (False Negative):** пропущенный дождь (не предсказан)

**Пример:**
```
Predicted: Rain    | Predicted: No Rain
--------------------|--------------------
TP = 45            | FN = 12
FP = 18            | TN = 200
```

Отсюда:
- Precision = 45 / (45 + 18) = 0.71
- Recall = 45 / (45 + 12) = 0.79
- F1 = 2 * (0.71 * 0.79) / (0.71 + 0.79) = 0.75

## Threshold (порог срабатывания)

Модель возвращает score [0.0 ... 1.0+], который интерпретируется как "вероятность дождя". Для бинарной классификации (дождь/не дождь) нужно выбрать threshold:

- **Низкий threshold (например, 0.3):** модель чаще предсказывает дождь → высокий recall, низкий precision (много ложных тревог)
- **Высокий threshold (например, 0.7):** модель осторожнее → высокий precision, низкий recall (пропускает дожди)

**Пример:**
- score = 0.4, threshold = 0.3 → предсказание: дождь
- score = 0.4, threshold = 0.5 → предсказание: не дождь

В отчётах `run_full_analysis.py` считаются метрики для трёх порогов: `[0.3, 0.5, 0.7]`.

## Ground Truth

Реальные данные осадков, относительно которых проверяется модель. Для rain-analysis используется:

- **Open-Meteo API:** исторические данные осадков для координат (latitude/longitude)
- Формат: массив значений `precipitation` (mm) с шагом 1 час

**Пример:**
```json
{
  "hourly": {
    "time": ["2026-07-20T00:00", "2026-07-20T01:00", ...],
    "precipitation": [0.0, 0.0, 1.2, 3.5, ...]
  }
}
```

**Интерпретация:**
- `precipitation > 0.1 mm` → дождь был (класс 1)
- `precipitation <= 0.1 mm` → дождя не было (класс 0)

Порог `0.1 mm` выбран эмпирически — ниже считается "след осадков" (не регистрируется сенсорами).

## Feature Engineering

Извлечение информативных признаков из сырых временных рядов (температура, влажность, давление). Для rain-analysis используются:

### Тренды (Trends)
Скорость изменения величины за окно времени (например, 1h, 3h, 6h).

**Пример:**
- `humidity_trend_1h`: изменение влажности за последний час
- `pressure_trend_3h`: изменение давления за последние 3 часа

Быстрый рост влажности (`humidity_trend_1h > 5%`) — сигнал приближающегося дождя.

### Пики (Peaks)
Максимальные/минимальные значения за окно.

**Пример:**
- `humidity_peak_6h`: максимальная влажность за последние 6 часов

### Разброс (Range)
Диапазон значений за окно (max - min).

**Пример:**
- `humidity_range_3h`: разница между максимальной и минимальной влажностью за 3 часа

Большой разброс может указывать на нестабильную погоду.

### Абсолютные значения
Текущее значение без учёта истории.

**Пример:**
- `current_humidity`: влажность в данный момент (важно само по себе — 95% почти всегда означает дождь)

## Temporal Windows (временные окна)

Отрезки времени, по которым вычисляются признаки. В rain-analysis используются:

- **1h:** короткие, быстрые изменения (резкий скачок влажности перед дождём)
- **3h:** средние тренды (медленное нарастание)
- **6h:** длинные тренды (фоновые изменения давления)
- **12h:** для медленных процессов (pressure-aware модели)

**Ратionale:** разные физические процессы происходят на разных временных масштабах. Короткие окна ловят быстрые события, длинные — медленные тренды.

---

## Model Score

Выход модели — число [0.0 ... 1.0+], интерпретируемое как "степень уверенности в дожде". Не обязательно настоящая вероятность (модель baseline использует взвешенную сумму признаков).

**Интерпретация:**
- `score < 0.3`: дождя скорее всего нет
- `0.3 <= score < 0.5`: слабый сигнал (модель не уверена)
- `0.5 <= score < 0.7`: средняя вероятность дождя
- `score >= 0.7`: высокая вероятность дождя

Точные границы зависят от калибровки модели и выбранного threshold.

## Baseline Model

Простая эвристическая модель (версия v0.1) с фиксированными коэффициентами для признаков. Используется как reference point для оценки сложных моделей.

**Зачем нужна:** чтобы проверить, что усложнения (ML, feature engineering, интеграция давления) действительно улучшают качество. Если новая модель не бьёт baseline — она бесполезна.

**Детали:** см. [BASELINE_MODEL.md](../docs/BASELINE_MODEL.md).

## Pressure-Aware Models

Экспериментальные модели, учитывающие давление (в дополнение к температуре и влажности). Реализованы в `scripts_utils/pressure_variants.py`.

**Варианты:**
- `model_pressure_aware`: базовая интеграция тренда давления
- `model_pressure_absolute`: использует и тренд, и абсолютный уровень давления
- `model_pressure_long_window`: длинные окна (6h/12h) для медленных трендов
- `model_pressure_triple_window`: три окна (3h/6h/12h) для разных временных масштабов
- `model_combined`: взвешенная комбинация всех моделей

**Детали:** см. [MODELS.md](https://github.com/Kickoman/rain-analysis/blob/master/docs/MODELS.md).

## Open-Meteo API

Бесплатный API для получения исторических и прогнозных данных погоды. Используется в rain-analysis для ground truth validation.

**Endpoint:**
```
https://api.open-meteo.com/v1/forecast?latitude=55.75&longitude=37.62&hourly=precipitation&past_days=7
```

**Возвращает:** почасовые данные осадков (mm) за указанный период.

**Лимиты:** 10,000 запросов/день (достаточно для разработки и тестирования).

## Home Assistant

Open-source платформа умного дома. В rain-analysis используется как источник данных сенсоров (температура, влажность, давление).

**Формат хранения:** SQLite база (обычно `/config/home-assistant_v2.db`), таблица `states` с записями состояний всех сенсоров по временным меткам.

**Пример записи:**
```
entity_id: sensor.datchik_klimata_temperatura
state: 23.5
last_changed: 2026-07-20 12:34:56
```
